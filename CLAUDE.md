# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Windows Forms desktop app (VB.NET, .NET 6, `net6.0-windows`) for printing quality-traceability labels on a production floor. Code, comments, and UI text are in Spanish. Solution: `EtiquetasV4.sln`; single project `EtiquetasV4/Etiquetas.vbproj` (assembly name `Etiquetas`).

## Commands

```
dotnet build EtiquetasV4.sln
dotnet run --project EtiquetasV4/Etiquetas.vbproj
dotnet publish EtiquetasV4/Etiquetas.vbproj -p:PublishProfile=FolderProfile   # -> bin\Release\ActualizacionEtiquetas
```

There are no tests or linters. Publish profiles (Folder and ClickOnce) live in `EtiquetasV4/My Project/PublishProfiles/`.

## Architecture

- **Entry point**: `My Project/Application.myapp` sets `MainForm = Form1`. `Form1` holds nearly all logic; the other forms are small dialogs.
- **Form1 has two panels that swap positions** (`IntercambiarPosiciones`) rather than being shown/hidden:
  - *Trazabilidad*: prints a label via `PrintDocument1_PrintPage`, which generates the serial number and inserts a record.
  - *Liberación* (QA release): looks up a record by serial, prints a release label via `PrintDocument2_PrintPage`, and updates that record. It is gated behind the `Liberacion` login dialog. The `Registro` button uses the same login, then opens the `Registro` form to add users.
- **The station mode comes from `Etiquetas/Area.txt`**. If it is `PIPING`, an extra "Rv" field is shown and printed. If it is `EMBARQUES`, Form1 hides the traceability UI and embeds the `Embarques` form (a shipping label) inside `panelTrazabilidad`.
- **Serial format**: `R{yy}{monthLetter}S{consecutivoGlobal:000000}`. Month letters run A–M and skip `I`. The global consecutive is recalculated from `BaseTxt.MaxConsecutivoGlobal()` before each print. Barcodes are text drawn with the **"Libre Barcode 39"** font (`TextBox7.Font`), wrapped in `*...*`, so that font must be installed on the machine.
- **Label layout is hard-coded pixel coordinates** in the `PrintPage` handlers.

### Persistence

Label records live in a **SQLite database shared with the planned Python vision/inference module** (see `docs/PLAN.md`):

- `db/schema.sql` is the single source of truth for the schema (`etiquetas`, `usuarios`, `inspecciones`). It is idempotent and embedded in the VB assembly as resource `schema.sql`. `EtiquetasV4/BaseSqlite.vb` applies it on first connection. Schema changes affect both apps: bump `PRAGMA user_version`.
- DB location: env var `TRAZA_DB` → else `<repo root>/datos/trazabilidad.db` (found by walking up to `EtiquetasV4.sln`) → else `<exe dir>/datos/trazabilidad.db`. `datos/` is git-ignored.
- Dates are stored as ISO `yyyy-MM-dd HH:mm:ss`; the printed label still shows `dd/MM/yyyy`. `serial` is `UNIQUE COLLATE NOCASE`. `estado` is `IMPRESA` → `LIBERADA`/`RECHAZADA`.

Station config is still in text files under `EtiquetasV4/Etiquetas/`, copied to the output dir and read from `AppContext.BaseDirectory\Etiquetas\`:

| File | Purpose |
|---|---|
| `Area.txt` | Station area/mode (`PIPING`, `EMBARQUES`, ...) |
| `Spot.txt` | Station spot name |
| `No_borrar_ni_abrir.txt` | Per-station individual label counter |
| `PassQA.txt` | QA users in plain text (`Usuario:` / `Contraseña:` / `----` blocks); to be moved to the `usuarios` table |

The original backend was SQL Server table `Quality_print_records`. `System.Data.SqlClient` is still referenced and leftover SQL Server code remains (`ActualizarAreaEnBaseDeDatos`, unused `dbConn*` fields, `Imports` in `Embarques.vb`). New data access goes through `BaseSqlite`.

## Repo notes

- `bin/`, `obj/`, `.vs/` are in `.gitignore`, but build outputs and Release archives (`*.7z`) were committed before that rule existed and are still tracked. Rebuilding will show diffs in them.
- Designer files (`*.Designer.vb`, `*.resx`) are generated by the VS WinForms designer. Keep manual edits in them minimal and consistent with what the designer would produce.
